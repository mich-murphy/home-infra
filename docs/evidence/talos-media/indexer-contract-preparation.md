## Implemented wire contract

- `GET /torznab/api?apikey=<synthetic-key>&t=caps`
- `GET /newznab/api?apikey=<synthetic-key>&t=caps`
- The same routes with `t=search` or `t=movie`; `q`, `tmdbid`, `imdbid`, `cat`,
  `offset`, and `limit` select the single controlled release.
- Empty query/test search returns one release. Exact `Proof Fixture`,
  `proof.fixture`, or the release title also match (case-insensitive). Unknown
  query/identifier/category or nonzero offset returns a valid empty feed, not a
  fabricated hit. Limits above one are accepted but at most one item is emitted;
  limit zero returns none. No general title search, TV/music/book search, or
  pagination beyond this one result is advertised.
- Caps advertise `q` for search, `q,imdbid,tmdbid` for movie, category 2000
  Movies / 2040 Movies/HD, and max/default limit 1. Unsupported search families
  are marked unavailable. Caps require the fixture key too.
- Extra fields (e.g. `extended`, `attrs`, `configured`, future provider fields)
  are bounded and ignored, never reflected, forwarded, interpreted as file paths,
  or treated as evidence that the associated feature is supported.
- Destination/file selectors named `url`, `host`, `path`, `redirect`,
  `redirect_uri`, `downloadurl`, or `destination` fail closed with HTTP 400.
  Other extension fields remain inert even if their values contain URLs.
- Wrong/missing key returns HTTP 403 with provider `<error code="100">`.
  Unknown routes return 404; unknown actions (`get` included) return 400.
  Non-GET/body/transfer-encoding requests fail closed. Generic error bodies do
  not echo the request. There are no `/api/v1/indexer` or Radarr API endpoints.
- RSS 2.0 uses `http://torznab.com/schemas/2015/feed` for Torznab response/attrs
  and `http://www.newznab.com/DTD/2010/feeds/attributes/` for Newznab.
  Each item has category/size/identifier attrs, fixed publication date, a stable
  protocol/payload-hash/basename-derived GUID, and a fixture-only enclosure/link.
  Torznab also has the engine's real infohash and one synthetic seeder/peer;
  Newznab uses the engine's NZB with one controlled message ID.
- URLs are exactly configured `artifact-base` plus `/artifact.torrent` or
  `/artifact.nzb`, never taken from Host, request authority, query fields, or
  another provider. Absolute-form request targets are rejected. The configured
  announce must equal that same base plus `/announce` or initialization fails.
- `GET /stats?apikey=<synthetic-key>` returns fixed-name aggregate counters only;
  no API keys, raw queries, base64 logs, payload data, request histories or client
  addresses are stored/logged. Use a synthetic key, never an application secret.

## Bounds and no-forwarding boundary

Provider-only bounds: 2,048-byte request line, 8,192 bytes total headers with
2,048-byte individual header lines, 32 query fields, 64-character parameter
names, 256-character values, one request per connection, no request body,
16,384-byte response ceiling, four concurrent workers and a four-entry accept
backlog. Socket I/O timeout is three seconds; header parsing additionally has a
three-second aggregate deadline (request-line read is separately bounded).
Counters have fixed names, a lock, and saturate at `2^63-1`. Busy connections are
closed, not queued without bound. No arbitrary file or upstream network client
exists in the provider. Header/request errors are sanitized and tracebacks are
suppressed. There is no runtime request-controlled DNS or forwarding path.

Artifact bases and binds currently accept **only canonical explicit-port IPv4
loopback HTTP**. DNS names, non-loopback destinations, credentials, path, query,
fragment and IPv6 are rejected. This is intentional offline fail-closed scope,
not a Kubernetes Service integration. A URL allowlist alone is not a substitute
for future owner-controlled egress policy.

The imported, unchanged download engine is separately bounded: payload <=2 MiB,
16 worker slots **per** HTTP/peer/NNTP listener, five-second I/O timeouts,
BEP3/NNTP 60-second session deadlines and existing command/piece limits. Its
HTTP parser and counters retain their pre-existing behavior; the new provider's
smaller header limits and saturating counters do **not** harden that separate
HTTP server. Combined CLI has up to 52 worker slots, not four. Review these
engine limitations before any broader exposure; this change does not authorize
or claim hardened untrusted-client deployment.

## Reuse and explicit owner-wiring interface

The module imports the existing engine by a fixed repository-relative path.
`Contract(shared_fixture, artifact_base, synthetic_key)` requires its actual
`Fixture` type and verifies announce/base agreement. It does not download,
rebuild from untrusted files, or proxy artifacts. `Server((loopback, port),
contract)` serves only the provider. An embedding owner must serve that **same**
Fixture via the engine HTTP/BEP3/NNTP servers. A passing provider test alone
cannot establish that the advertised artifact service exists or is reachable.

The optional offline CLI starts both engines in **one process**, sharing one
Fixture/payload, rather than silently counting two independent 128-MiB fixtures
as one. Example for caller-owned disposable loopback ports only:

```sh
python3 kubernetes/apps/media/fixtures/indexer-contract/server.py \
  --api-key OfflineSyntheticKey42 --port 8090 \
  --artifact-base http://127.0.0.1:8080 --peer-port 6881 --nntp-port 8119
```

This example is not a command to run against a host/cluster. No listeners are
started just by importing the module. The default input is synthetic binary,
**not importable movie media**. For later media use, `--payload` loads only a
caller-owned regular read-only input, using the existing no-symlink/path-walk,
nonempty <=2-MiB loader. The program does not create or overwrite input files,
artifacts, app destinations or downloads in app PVCs. Caller must provide an
appropriate safe basename with `--name`; the advertised quality title is a
fixture convention, not proof of actual codec/quality.

The existing immutable 2-second and 12-second artifacts must not be overwritten.
A 12-second H264 clip can trigger Arr sample rejection. A future separate
procedurally generated >=2-minute (or 10-minute), low-frame-rate H264/AAC clip
<=2 MiB is an option, with explicit **fixture-only** quality/size/sample overrides
if needed. Neither generating it nor changing production quality defaults is
part of this preparation. Skyhook's existing one-minute runtime is unchanged;
any future runtime consistency change also needs its owner.

Cross-pod artifact-base/announce/listener integration deliberately fails closed
now. Owner wiring must explicitly solve reachable canonical advertised addresses,
shared payload/engine lifecycle, destination policies, read-only input mounting,
readiness, provider auth vs Prowlarr's own app auth, and aggregate fixture resource
accounting. Do not simply relax loopback validation or start a second uncharged
fixture and call the integration done. No new manifest or live harness is added.
