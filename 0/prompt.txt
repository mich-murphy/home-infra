## PART 2 — RESEARCH / RECOMMENDATIONS (TRaSH Guides)

Goal (per correction from parent): **prefer dual/multi-audio releases (original language + English) over original-only; accept original-only if no dual/multi release exists; reject English-dub-only releases** (i.e. releases missing the original-language track entirely).

Sources: [How to set up Language Custom Formats](https://trash-guides.info/Radarr/Tips/How-to-setup-language-custom-formats/) (and its raw JSON includes on GitHub), [Radarr Collection of Custom Formats](https://trash-guides.info/Radarr/Radarr-collection-of-custom-formats/), [How to set up Quality Profiles](https://trash-guides.info/Radarr/radarr-setup-quality-profiles/), [Buildarr Radarr quality-profile reference](https://buildarr.github.io/plugins/radarr/configuration/settings/profiles/quality-profiles/), [Recyclarr quality-profiles reference](https://recyclarr.dev/reference/configuration/quality-profiles/), and Radarr GitHub issues on MULTi parsing (#8328, #8382, #7262, #6592, #10842, #10819).

### A. Quality profile `language` setting: Any vs Original vs English
TRaSH's explicit warning (verbatim from the guide):
&gt; "Using language Custom Formats is not compatible with setting a preferred language in a quality profile in Radarr. You must use one or the other. If you want to make use of the Custom Formats set the preferred language to `Any`."

- **`English`** (what 6 of your 7 profiles currently use) makes Radarr's own language filter reject any release it doesn't parse as containing English at all — this is the crude, inflexible mechanism and it's incompatible with fine-grained CF scoring.
- **`Original`** (what profile #7 currently uses) makes Radarr require the movie's original-language track and nothing else as a hard filter — again incompatible with CF-based scoring, and it would actually reject English-only dubs by itself, but it can't *express* "prefer dual audio, tolerate original-only."
- **`Any` + custom-format scoring** is the flexible approach TRaSH recommends whenever you want nuanced language preferences (prefer-but-don't-require patterns like this task). **To implement the requested behavior, every profile touching foreign-language movies needs `language = Any`, replacing the current `English`/`Original` settings.**

### B. Custom formats needed (exact JSON, verbatim from TRaSH's repo)

**1. Reject releases missing the original-language track** (blocks English-dub-only) — TRaSH calls this "Wrong Language" (superseding the older "Language: Not Original" pattern), score **-10000**:
```json
{
  "name": "Wrong Language",
  "includeCustomFormatWhenRenaming": false,
  "specifications": [
    {
      "name": "Wrong Language",
      "implementation": "LanguageSpecification",
      "negate": true,
      "required": true,
      "fields": { "value": -2, "exceptLanguage": false }
    }
  ]
}
```
(`value: -2` = Original; `negate: true` means "match releases that do NOT have the original language"; that match gets the -10000 score, so any release lacking the original track is effectively unusable at any quality tier.)

**2. Prefer dual/multi-audio (original + English) as an upgrade.** TRaSH's real-world template for exactly this pattern is `"Language: Original + French"` (id `0542a48746585dc4444bbbb8a6bdf6ea`) — substitute French(`2`)→English(`1`):
```json
{
  "name": "Language: Original + English",
  "includeCustomFormatWhenRenaming": false,
  "specifications": [
    {
      "name": "Original Language",
      "implementation": "LanguageSpecification",
      "negate": false,
      "required": true,
      "fields": { "value": -2 }
    },
    {
      "name": "English Language",
      "implementation": "LanguageSpecification",
      "negate": false,
      "required": true,
      "fields": { "value": 1 }
    },
    {
      "name": "MULTi",
      "implementation": "ReleaseTitleSpecification",
      "negate": false,
      "required": true,
      "fields": { "value": "\\b(MULTi)(\\b|\\d)" }
    }
  ]
}
```
Assign a solidly positive score (TRaSH's own French analogue uses 500 in some of its regional profiles). Because all three specs are `required: true`, **all three must match (AND) for the format to apply** — the release must be tagged Original AND English AND carry a MULTi marker in the title. This positively rewards true dual-audio releases without needing the negative CF above (that one independently guards against English-only dubs).

**3. (Optional but recommended) Generic "MULTi" release-title detector**, used elsewhere in the guide as a title-only signal (not itself scored, or scored lightly), useful if you also want to catch dual-audio releases whose *title* says MULTI but whose parsed language list Radarr hasn't fully populated yet (see MULTI-parsing caveat below):
```json
{
  "name": "MULTi",
  "includeCustomFormatWhenRenaming": true,
  "specifications": [
    {
      "name": "Multi",
      "implementation": "ReleaseTitleSpecification",
      "negate": false,
      "required": true,
      "fields": { "value": "\\b(Multi)(?![ ._-]?sub(s)?)(\\b|\\d)" }
    }
  ]
}
```
Regex deliberately excludes "Multi-subs" false positives.

**4. Anime-specific pattern**, relevant since one of your indexers is AnimeBytes — `"Anime Dual Audio"` (trash_id `4a3b087eea2ce012fcc1ce319259a3be`) uses a broader regex plus optional `LanguageSpecification` for Japanese/Chinese/Korean and explicitly excludes `[JA]`/`[ZH]`/`[KO]`-only tags:
```json
{
  "name": "Anime Dual Audio",
  "includeCustomFormatWhenRenaming": false,
  "specifications": [
    { "name": "Dual Audio", "implementation": "ReleaseTitleSpecification", "negate": false, "required": true,
      "fields": { "value": "dual[ ._-]?(audio)|[([]dual[])]|\\b(JA|ZH|KO)(?= ?\\+ ?.*?\\b(EN))|\\b(EN)(?= ?\\+ ?.*?\\b(JA|ZH|KO))|\\b(Japanese|Chinese|Korean) ?[ ._\\+&amp;-] ?\\b(English)|\\b(English) ?[ ._\\+&amp;-] ?\\b(Japanese|Chinese|Korean)|\\b(\\d{3,4}(p|i)|4K|U(ltra)?HD)\\b.*\\b(DUAL)\\b(?!.*\\(|\\))" },

```

**Also worth knowing:** TRaSH ships a `"Bad Dual Groups"` CF (-10000) that blocks a specific denylist of release groups known to mislabel/mis-mux dual-audio releases (wrong track order breaking ffprobe language detection → import failures) — not essential for this task but relevant if dual-audio imports start behaving oddly after this change.

### C. How Radarr combines specification logic in a Custom Format
Confirmed from the TRaSH examples themselves (e.g. "Language: Not Dutch" uses two `negate:true, required:true` specs to implement "penalize unless Dutch OR Flemish present," via De Morgan's law):
- **All `required: true` specifications must match (AND)** for the CF to apply.
- **Among the `required: false` (optional) specifications, at least one must match (OR)** — if optional specs exist, one match among them is enough.
- Negation flips what "match" means for that individual spec, but the AND/OR combination rule above still governs multi-spec formats.
- This is exactly how the "Original + English" CF above enforces "original present AND English present AND MULTi-tagged" as a single AND'd condition.

### D. Score-threshold fields — how to actually make Radarr search for upgrades
Per Buildarr/Recyclarr/TRaSH docs, three fields control this (all present in your `/api/v3/qualityprofile` payload):
- **`minFormatScore`** ("Minimum Custom Format Score"): a hard floor — any release scoring below this is rejected outright regardless of quality.
- **`cutoffFormatScore`** ("Upgrade Until Custom Format Score"): the ceiling Radarr will keep upgrading toward (via custom-format score) once the quality cutoff itself is already satisfied. **Your profiles 1–6 currently have this at `0`, which means no CF-based upgrade searching happens in them at all** — this must be raised to at least the score you give the "Original + English" CF (e.g. ≥500, or whatever value chosen) or Radarr will never bother searching for a dual-audio replacement once an original-only file is already downloaded.
- **`minUpgradeFormatScore`**: the minimum score *increase* a candidate release must offer over the currently-grabbed file to be treated as a worthwhile upgrade (anti-thrashing guard against near-tied scores). Currently `1` on every profile — fine to leave as-is, or raise slightly.

Putting it together for the desired behavior: an original-only release scores `0` (neither the negative "Wrong Language" CF nor the positive "Original + English" CF match it) → accepted since `0 ≥ minFormatScore(0)`. A dual/multi release scores e.g. `+500` → also accepted, and because `500 &gt; 0`, once `cutoffFormatScore` is raised above 0 Radarr will keep monitoring/searching and grab the dual-audio release as an upgrade over the original-only file already on disk. An English-dub-only release scores `-10000` (fails "Wrong Language") → always rejected outright, never grabbed even as a first pass.

### E. How Radarr detects "MULTi"/dual-audio from a release title, and its limitations
- Radarr's parser (`src/NzbDrone.Core/Parser/LanguageParser.cs`) scans the release title for known language names/tags (e.g. explicit language words, `VOSTFR`, `TRUEFRENCH`, `MULTi`, `DUAL`) and populates a `Languages` list purely from what it can textually recognize — **it has no access to actual embedded audio tracks** (MediaInfo parsing of audio language happens separately during import/rename, not during search-time filtering).
- **Per-indexer "Multi Languages" setting** (the `multiLanguages` field seen empty on all 5 of your indexers): this tells Radarr "when this indexer's release title just says MULTI with no language list, assume the release contains these specific languages (e.g. Original + Polish)." **Because this is unset everywhere, a bare "MULTI" tag with no explicit language names in the title currently resolves to almost no usable language information** for the CFs above to act on reliably. TRaSH/community guidance and the Radarr GitHub issue tracker (#8382 "Radarr shows English release for a multi-language release", #7262 "Radarr pulling multi-language at the expense of format/profile score", #8328 "Release Parser multi tag is not working", #10842 fixing "MULTI + a named language in title only registers the named language, drops MULTI's implied languages") confirm this is a known, still-imperfect area — **setting `multiLanguages` on each indexer (e.g. to `Original` + `English`) is recommended alongside the CF changes**, otherwise many genuinely dual-audio releases will be invisible to the "Original + English" CF because Radarr never populated their `Languages` list correctly.
- Bottom line limitation to flag to the user: Radarr's language detection is entirely release-title-text-based at search/decision time; it cannot inspect actual muxed audio streams before download, so no CF configuration can be 100% accurate — mislabeled or under-labeled releases (bare "MULTi" with no language list, or non-standard tagging) will sometimes slip through incorrectly in either direction.
